# UX Excellence Framework

> **철학**: 사용자가 "쓰기 쉽다"라고 느낄 때는 이미 평범한 제품. 우리는 "이 제품은 나를 이해한다"라고 느끼게 만든다.
>
> **목표**: 사용자가 이 제품을 쓰고 나서 **"다른 제품이 불편해졌다"** 고 말하게 하는 것.

이 문서는 모든 페이지·컴포넌트·인터랙션에 적용되는 **횡단 기준**입니다. Claude Code가 UI 작업을 할 때 반드시 참조해야 합니다.

---

## Part I. 파운데이션 — 5대 설계 원칙

### 원칙 1. 예측 가능성 (Predictability)

사용자는 클릭 전에 **무슨 일이 일어날지** 알아야 한다.

- 버튼 라벨이 결과를 묘사 ("확인" ❌ / "5개 페르소나 생성하기" ✅)
- 돌이킬 수 없는 액션은 2단계 확인 + 명확한 경고 색상
- 숨은 상태 변화 금지 — 백그라운드 저장도 반드시 인디케이터

### 원칙 2. 역주행 가능성 (Reversibility)

실수는 제품의 잘못이다.

- 기본적으로 모든 삭제는 **소프트 딜리트**, P2에서 휴지통 UI
- 되돌리기 불가 액션은 명시적으로 경고
- 실시간 자동 저장 + 히스토리 — 사용자는 저장 걱정 안 함

### 원칙 3. 점진적 공개 (Progressive Disclosure)

필요한 정보만, 필요한 순간에.

- 초기 화면은 2~3개 옵션만 (핵심 액션 명확)
- 고급 설정은 "고급 옵션" 토글 뒤에
- 첫 사용자는 가이드, 숙련자는 생산성 — **같은 UI, 다른 경로**

### 원칙 4. 체감 속도 (Perceived Performance)

실제 속도보다 "빠르다는 느낌"이 우선.

- 모든 액션은 **50ms 이내 시각적 반응**
- 로딩이 필요하면 진행률 표시
- 스켈레톤 UI로 레이아웃 변동 제로

### 원칙 5. 신뢰와 투명성 (Trust & Transparency) — AI 제품 특화

AI가 하는 모든 일을 사용자가 이해하고 통제할 수 있어야 한다.

- "AI가 판단한 이유" 항상 표시 가능
- 비용·시간·영향 범위 사전 고지
- 언제든 사용자가 수정·거부 가능

## Part II. 인터랙션 표준

### 2.1 폼 · 입력

| 요구사항     | 상세                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 실시간 검증   | `onBlur`: 에러 표시, `onChange`: 에러 **숨김**(입력 방해 X)                                                            |
| 제출 시 실패  | ① 첫 에러 필드로 smooth scroll (600ms easeOutQuart) → ② 포커스 이동 → ③ 인라인 에러 + 해결 방법 → ④ 상단 요약 배너 ("3개 항목을 확인해주세요") |
| 자동 저장    | 입력 후 3초 디바운스 → PATCH → 헤더에 "방금 저장됨" fade in 300ms                                                          |
| 글자 수 카운터 | 80% 경고(주황), 100% 에러(빨강), `현재/최대` 형식 (`287 / 500`)                                                          |
| 입력 힌트    | placeholder는 "예:" 형식 (`예: "30대 직장인 여성"`)                                                                   |
| 필수/선택    | 필수가 기본, 선택은 `(선택)` 라벨 (별표 대신)                                                                              |
| 자동완성     | `autocomplete="email"`, `current-password` 등 명시                                                            |
| 복사 붙여넣기  | 민감 필드(비밀번호 확인) 외엔 모두 허용                                                                                    |
| 한글 IME   | 조합 중(isComposing) 제출·검증 트리거 금지                                                                             |
| 탭 이동 순서  | 논리적 순서(`tabIndex`)로 키보드만 완료 가능                                                                             |

### 2.2 버튼 · 액션

| 요구사항        | 상세                                        |
| ----------- | ----------------------------------------- |
| 클릭 즉시 반응    | 50ms 이내 눌림 효과 (scale 0.97 + 색상 변화)        |
| 비동기 액션      | 스피너 + 라벨 변경 ("저장하기" → "저장 중...") + 비활성화   |
| 중복 클릭 방지    | 진행 중엔 `disabled` + `pointer-events: none` |
| 200ms 이내 응답 | 스피너 **생략** (반대로 깜빡임이 더 이질감)               |
| 2초 경과       | "조금 더 걸려요..." 보조 텍스트 추가                   |
| 파괴적 액션      | 빨강 버튼 + 재확인 모달 + 이름 재입력                   |
| 주요/보조 위계    | 한 화면 Primary 버튼 **1개만** (예외 시 정당성 필요)     |

### 2.3 네비게이션 · 상태 보존

| 요구사항   | 상세                                   |
| ------ | ------------------------------------ |
| 뒤로가기   | 브라우저 기본 동작 + 스크롤 위치 복원               |
| 이탈 경고  | 작성 중 데이터 있을 때 `beforeunload`         |
| 딥링크    | URL에 상태 보존 (예: `?tab=guided&step=3`) |
| 세션 복구  | 탭 닫은 후 복귀 시 "이어서 작성하시겠어요?" 모달        |
| 스크롤 위치 | 리스트→상세→뒤로가기 시 원래 위치 복원               |

## Part III. 피드백 시스템

### 3.1 4계층 피드백

| 유형          | 형식               | 지속       | 색상    | 용도             |
| ----------- | ---------------- | -------- | ----- | -------------- |
| **Success** | Toast (우상단)      | 4초       | 초록    | 저장, 전송, 완료     |
| **Error**   | Toast + [다시 시도]  | 8초 또는 수동 | 빨강    | 일시적 실패         |
| **Warning** | Banner (인페이지 상단) | 수동       | 주황    | 이메일 미인증, 예산 임박 |
| **Info**    | Tooltip / Inline | 영구       | 파랑/회색 | 도움말            |

### 3.2 토스트 동작 규칙

- 같은 유형 3개 이상 누적 → **스택** 표시 (화면 덮지 않음)
- 중요 에러는 **자동 소멸 X**
- 토스트 내 액션 **최대 1개**
- 호버 시 **타이머 일시정지**

### 3.3 파괴적 액션 확인 모달

```
[ 프로젝트 "매스소나" 삭제 ]

이 작업은 되돌릴 수 없습니다.
아래 모든 데이터가 영구 삭제됩니다:
• 페르소나 그룹 3개 (100명)
• 리서치 세션 1건
• 리포트 1건

확인을 위해 프로젝트명을 입력해주세요:
┌──────────────────────────┐
│                          │
└──────────────────────────┘

             [ 취소 ]  [ 영구 삭제 ]
                       ↑ 빨강, 이름 일치 시 활성
```

### 3.4 Undo 패턴 (P2)

- 삭제는 소프트 딜리트 + "삭제됨. [되돌리기]" 8초 토스트
- 8초 내 복구, 이후 실제 삭제
- **P1 구현**: `deletedAt` 필드만 스키마에 반영

## Part IV. 로딩 · 대기 경험

### 4.1 로딩 3 등급

| 시간         | 처리                               |
| ---------- | -------------------------------- |
| < 200ms    | 스피너 금지. 즉시 완료로 보이게               |
| 200ms ~ 2초 | 스피너 + 불투명 오버레이                   |
| 2초 ~ 10초   | 진행률 바 + 단계 표시 ("파일 분석 중... 2/3") |
| 10초 초과     | **AI 리서치 전용 경험 UI** (4.2)        |

### 4.2 AI 리서치 대기 — Massona 핵심 UX

100명 × 5질문 = 수 분. 이 시간을 **설계된 경험**으로.

1. **리얼타임 카운터**: "47/100 응답 완료"
2. **페르소나 모자이크**: 완료된 페르소나 색 채움, 대기 중은 회색
3. **샘플 응답 스트림**: 흥미로운 응답 3개 미리 하이라이트
4. **예상 남은 시간**: "약 2분 남음" (±30% 정확성)
5. **브라우저 알림**: 탭 이탈 시 완료되면 알림 (권한 요청)
6. **중단 가능**: [잠시 중단] 버튼 — 완료 응답 보존

### 4.3 스켈레톤 UI 규칙

- 실제 레이아웃과 동일한 형태 (Layout Shift = 0)
- 1.5초 펄스 애니메이션 (`opacity 40% → 70% → 40%`)
- 200ms 이상일 때만 표시
- 카드·리스트·차트 각각 전용 스켈레톤

## Part V. 빈 상태 · 첫 경험

### 5.1 빈 상태는 온보딩이다

빈 화면은 "데이터 없음"이 아니라 **"다음 할 일을 알려주는 순간"**.

**필수 구성 요소 (5개 모두)**:

1. 일러스트 (귀엽지만 유치하지 않게)
2. 헤드라인 (공감, 8자 이내)
3. 서브카피 (왜 비었는지 + 어떻게 채우는지, 20자 이내)
4. Primary CTA
5. 보조 링크 (예시 보기, 가이드 읽기)

### 5.2 첫 사용자 온보딩 접점

| 접점              | 처리                                |
| --------------- | --------------------------------- |
| 최초 가입 완료        | 대시보드에 "첫 프로젝트 만들기" 튜토리얼 카드        |
| Quick Setup 입력창 | 텍스트 없을 때 **예시 3개 회전** placeholder |
| 빈 페르소나 리스트      | AI 샘플 페르소나 미리보기                   |
| 리서치 세션 첫 진입     | 질문 예시 **칩** 3개 (클릭 → 삽입)          |
| 리포트 첫 확인        | 각 섹션 상단 "이 섹션 읽는 법" 3초 툴팁         |

### 5.3 Empty-by-default, Rich-by-action

첫 화면은 **비어있되 초대하는 상태**. 컨텐츠는 사용자 행동 뒤에.

## Part VI. 콘텐츠 · 보이스

### 6.1 보이스 가이드 (한국어)

| 차원  | 스탠스            | 예시                                     |
| --- | -------------- | -------------------------------------- |
| 톤   | 친근, 프로페셔널      | "어떤 사용자를 만나볼까요?" (O) / "유저를 입력하시오" (X) |
| 주어  | 유저 또는 시스템 명시적  | "AI가 3개 그룹을 추천해요"                      |
| 시제  | 과거·현재·미래 엄격 구분 | "저장했어요" / "저장하고 있어요" / "저장할게요"         |
| 부정형 | 사과 대신 행동       | "다시 시도해주세요" (O) / "죄송합니다" (X)          |
| 수치  | 맥락 포함          | "100명 중 23명이 긍정 응답" (O) / "23%" 단독 (X) |

### 6.2 마이크로카피 원칙

- 버튼: **동사**로 시작 ("저장하기", "시작하기")
- 에러: **문제 + 해결** 세트 ("비밀번호가 일치하지 않아요. 다시 확인해주세요.")
- 빈 상태: **공감 + 행동** ("아직 프로젝트가 없네요. 첫 리서치를 시작해볼까요?")
- 로딩: **상태 + 예상 시간** ("페르소나 생성 중... 약 30초")

### 6.3 금지어 · 금지 패턴

❌ "클릭해주세요" → "선택해주세요"
❌ "오류가 발생했습니다" → "저장에 실패했어요. 네트워크를 확인해주세요"
❌ "처리 중입니다" → "페르소나 100명 생성 중이에요"
❌ "잠시만 기다려주세요" → "약 2분 남았어요"
❌ "유효하지 않습니다" → "100자 이상 입력해주세요"
❌ "죄송합니다" (에러 앞) → 바로 행동으로
❌ "이용자", "고객", "회원" → "당신" 또는 이름
❌ 불필요한 확인 모달 ("정말로 저장하시겠어요?")

## Part VII. AI 특화 UX (Massona 핵심 차별화)

### 7.1 AI 투명성

| 상황       | 처리                                        |
| -------- | ----------------------------------------- |
| AI 세팅 결과 | "이렇게 판단한 이유" 토글 — 어떤 입력을 보고 왜 이 그룹을 만들었는지 |
| 페르소나 카드  | "근거 보기" — 4축 JSON 출처 설명                   |
| 응답 사고과정  | 기본 숨김, "AI의 생각 과정 보기" 토글                  |
| 리포트 인사이트 | 요약문 옆 "근거가 된 응답 3개" 펼치기                   |

### 7.2 AI 통제권

- 모든 AI 생성물 **수정 가능** (P1: 그룹 비율, P2: 개별 편집)
- 이상한 응답 "이 응답 재생성" 플래그 (P2)
- AI 추천 질문 개별 삭제·순서 변경·추가 가능

### 7.3 비용 투명성 (월 $100 예산)

- 세션 시작 전 **예상 비용 프리뷰**: "약 $1.2 예상 (GPT-4o-mini 기준)"
- 진행 중 **실시간 누적 비용**: 우하단 뱃지 `$0.47 / $1.20`
- 월 예산 80% 도달 시 **배너 경고**

### 7.4 AI 대기 시간 품질

- **"AI가 지금 무엇을 하는지"** 한 줄 실시간 업데이트
  - "페르소나 그룹 구조 설계 중..."
  - "47번째 페르소나 응답 수집 중..."
  - "공통 인사이트 분석 중..."
- 실제 API 상태를 번역한 **진짜 정보**여야 함 (가짜 단계 금지)

## Part VIII. 접근성 · 포용성

### 8.1 준수 레벨

**WCAG 2.1 Level AA** 목표.

### 8.2 구체 기준

| 영역     | 요구                                    |
| ------ | ------------------------------------- |
| 색상 대비  | 본문 4.5:1, 제목·큰 텍스트 3:1                |
| 키보드    | 모든 기능 키보드만으로 완수, `Tab` 논리적 순서         |
| 포커스 링  | 보이는 outline (`ring-2 ring-offset-2`)  |
| ARIA   | 동적 콘텐츠 `aria-live`, 에러 `role="alert"` |
| 스크린리더  | 아이콘 버튼 `aria-label`, 장식 이미지 `alt=""`  |
| 줌      | 200%까지 깨지지 않음                         |
| 모션 최소화 | `prefers-reduced-motion` → 애니메이션 제거   |
| 폰트 크기  | 기본 16px, rem 단위 사용                    |
| 다크 모드  | **P2 지원**, P1은 CSS 변수 구조만 대비          |

### 8.3 국제화 준비

- 모든 텍스트 `/locales/ko.json` 분리 (하드코딩 금지)
- 날짜·숫자 포맷 유틸 분리 (`formatDate`, `formatNumber`)
- 공간 여유 (영어는 20~40% 길어질 수 있음)

## Part IX. 반응형 · 다중 디바이스

### 9.1 브레이크포인트

```
sm:  375px  (모바일 - 최소 지원)
md:  768px  (태블릿)
lg:  1024px (랩톱 - 주요 타겟)
xl:  1440px (데스크톱)
```

### 9.2 디바이스별

| 디바이스          | 특이사항                                   |
| ------------- | -------------------------------------- |
| 모바일(375~767)  | 긴 폼 → Sticky 하단 CTA, 드래그앤드롭 → 탭 업로드 폴백 |
| 태블릿(768~1023) | 2단 그리드, 랜드스케이프 대응                      |
| 랩톱(1024~1439) | **주 타겟** — 모든 기능 최적화                   |
| 데스크톱(1440+)   | 최대 너비 1280px (너무 넓으면 읽기 어려움)           |

### 9.3 터치 인터페이스

- 터치 타겟 최소 **44×44px**
- 스와이프는 보조 (주요 기능 대체 X)
- 호버만으로 접근 가능한 기능 **금지**

## Part XI. 에러 예방 > 에러 처리

### 11.1 에러는 사용자의 잘못이 아니다

- 예방 우선 — 숫자 입력은 number input, 잘못된 파일은 업로드 차단
- 방지 메시지 — "1,000명은 약 $30 비용이 예상돼요"
- 복구 경로 제공 — 어떤 에러든 **다음 행동** 제시

### 11.2 에러 카피 4단계

```
[ 1. 공감 ] — 사용자 혼란 인지
[ 2. 설명 ] — 무엇이 왜 안 됐는지 (기술용어 X)
[ 3. 해결 ] — 사용자가 할 수 있는 행동
[ 4. 대안 ] — 위가 안 되면 어떻게?
```

**예**:

> 파일을 업로드하지 못했어요.
> 파일 크기가 12MB로 허용 한도(10MB)를 넘어요.
> 파일을 10MB 이하로 줄이거나, 내용을 텍스트로 복사해서 상황 설명에 직접 붙여넣어주세요.
> 도움이 필요하면 [고객센터]로 연락주세요.

### 11.3 에러 회복 패턴

| 에러         | 자동 처리                | 사용자에게                               |
| ---------- | -------------------- | ----------------------------------- |
| 네트워크 일시 장애 | 재시도 3회 (exp backoff) | 10초 이상 시 "연결이 불안정해요. 계속 기다리시겠어요?"   |
| LLM 응답 실패  | P2: Fallback 모델      | P1: "1명 실패, 99명 성공" + 재시도 버튼        |
| 세션 타임아웃    | 자동 갱신 시도             | 실패 시 "다시 로그인해주세요" + 작성 내용 자동 저장됨 강조 |
| 파일 업로드 실패  | 3회 재시도               | 실패 후 "파일만 다시 업로드" (다른 입력 유지)        |

## Part XIII. 디테일의 품격

### 13.1 마이크로 인터랙션

| 요소        | 애니메이션                          | 지속                 |
| --------- | ------------------------------ | ------------------ |
| 버튼 hover  | scale 1→1.02, 색상 shift         | 150ms              |
| 버튼 active | scale 0.97                     | 100ms              |
| 모달 open   | opacity 0→1, scale 0.95→1      | 200ms easeOutQuart |
| 토스트       | 우측에서 slide-in                  | 300ms              |
| 카드 hover  | subtle shadow lift (`y: -2px`) | 150ms              |
| 체크박스      | 체크 애니메이션 spring                | 200ms              |

### 13.2 감성 요소 (선택)

- 첫 리포트 완료 시 **축하 콘페티** (단 1회, 기억)
- 100번째 프로젝트 시 작은 메시지
- 연속 7일 사용 시 "꾸준하시네요 🌱" (P2)

### 14.2 페이지 명세 템플릿 `[UX 체크]` 항목

```markdown
> **[UX 체크] — 페이지명**

> - [ ] 폼 제출 실패 시 스크롤+포커스+인라인 에러+상단 요약 4단계?
> - [ ] 로딩 > 2초 액션에 진행률/예상시간?
> - [ ] 파괴적 액션에 재확인 모달 + 이름 재입력?
> - [ ] 모든 카피가 금지어 위반 없음?
> - [ ] 키보드만으로 완주 가능?
> - [ ] 모바일 375px에서 깨지지 않음?
> - [ ] AI 요소에 "이유 보기" 제공?
> - [ ] 에러 카피 4단계 준수?
> - [ ] 애니메이션이 prefers-reduced-motion 존중?
> - [ ] autocomplete · aria-label · role 속성 적절?
> - [ ] 스크린리더 낭독 테스트 통과?
```

- 12상태 모두 스크린샷 확인

## Part XVI. 안티패턴 — 하지 말 것

❌ "죄송합니다만..." 으로 시작하는 모든 에러
❌ 불필요한 확인 모달 남발
❌ 로딩 스피너만 던지기 (무엇을? 언제까지?)
❌ 에러 코드 노출 ("ERR_5041")
❌ 플레이스홀더를 레이블로 (입력 시 사라짐 → 접근성 파괴)
❌ Primary 버튼 2개 이상 한 화면
❌ Tooltip만으로 정보 제공 (모바일 접근 불가)
❌ 빈 상태 "데이터가 없습니다" 텍스트만
❌ 스크롤 hijacking · 비표준 스크롤
❌ 색상만으로 상태 구분 (아이콘 · 텍스트 병행 필수)

## 요약 — "압도적 UX"의 7가지 조건

1. **예측 가능** — 사용자가 다음을 안다
2. **되돌릴 수 있음** — 실수가 상처가 안 됨
3. **기다림이 즐거움** — 대기 시간조차 설계됨
4. **AI가 투명함** — 블랙박스가 아님
5. **디테일이 살아있음** — 마이크로 인터랙션·카피·타이밍
6. **모두에게 열림** — 접근성이 기본
7. **사용자 편임** — 에러는 제품의 잘못

이 7가지 조건을 모든 기능에 질문하며 개발한다.
